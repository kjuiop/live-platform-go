현재 GitHub 이슈를 분석해 `docs/claude/` 아래에 상세 구현 계획 문서를 작성합니다.

추가 컨텍스트: $ARGUMENTS

다음 순서로 진행하세요:

## 1. 현재 이슈 파악

아래 명령어를 병렬로 실행해 컨텍스트를 수집합니다:
- `gh issue list --state open --limit 10` — 열린 이슈 목록 확인
- `git branch --show-current` — 현재 브랜치 확인
- 현재 브랜치명이 이슈 번호를 포함하면 해당 이슈를 특정합니다 (예: `feat/issue-3-...` → 이슈 #3)
- 브랜치에서 이슈를 특정할 수 없으면 `gh issue list` 결과 중 가장 최근 이슈를 대상으로 합니다
- 특정된 이슈에 대해 `gh issue view {번호}` 로 상세 내용을 읽습니다

`$ARGUMENTS`가 있으면 이슈 내용과 함께 추가 컨텍스트로 활용합니다.

## 2. 코드베이스 파악

이슈 내용을 바탕으로 관련 파일/패키지를 파악합니다:
- 프로젝트 구조 확인 (주요 디렉터리, 기존 패키지)
- 이슈와 관련된 기존 코드가 있으면 읽어서 현재 상태를 파악합니다

## 3. 문서 파일명 결정

- 형식: `docs/claude/issue-{번호}-{짧은-슬러그}.md`
- 예시: `docs/claude/issue-3-go-project-init.md`
- `docs/claude/` 디렉터리가 없으면 생성합니다

## 4. 계획 문서 작성

아래 구조로 문서를 작성합니다. 각 섹션을 최대한 구체적으로 채웁니다:

```markdown
# Issue #{번호}: {이슈 제목}

## 개요

{이슈가 해결하려는 문제와 목표를 2~3문장으로 설명}

---

## 배경 지식 & 관련 개념

{각 개념마다 소제목을 붙입니다}

### {개념 1}
{설명, 동작 원리, 이 프로젝트에서 왜 필요한지}

### {개념 2}
...

---

## 구현 계획

### Step 1: {단계 제목}
**목표**: {이 단계에서 달성해야 할 것}

**작업 내용**:
- {세부 작업}
- {세부 작업}

**코드 샘플** (참고용):
\```{언어}
{실제로 사용할 수 있는 구체적인 코드 예시}
\```

**주의사항**:
- {이 단계에서 놓치기 쉬운 것, 알아야 할 트레이드오프}

### Step 2: {단계 제목}
...

---

## 파일/디렉터리 구조 (예상)

\```
{구현 후 예상되는 파일 트리}
\```

---

## 검증 방법

- {완료 후 동작을 확인하는 방법 — 명령어, 테스트, 로그 등}

---

## 참고 링크

- [{제목}]({URL})
```

작성 규칙:
- 코드 샘플은 **복사해서 바로 참고할 수 있는 수준**으로 구체적으로 작성합니다 (변수명, 설정값 포함)
- 각 Step은 독립적으로 완료/확인 가능한 단위로 나눕니다
- 이 프로젝트의 기술 스택(Go 1.23, Gin, Gorilla WebSocket, Kafka, Redis)과 컨벤션에 맞게 작성합니다
- 배경 지식 섹션은 개념을 처음 접하는 사람도 이해할 수 있을 만큼 자세히 작성합니다

## 5. 결과 출력

- 생성된 문서 경로
- 다룬 이슈 번호 및 제목
- Step 목록 요약 (한 줄씩)

주의사항:
- Go 코드를 직접 프로젝트 파일에 작성하거나 수정하지 않습니다 — 문서만 작성합니다
- `$ARGUMENTS`가 비어있어도 이슈를 자동으로 파악해 진행합니다
- 이슈를 특정할 수 없으면 사용자에게 이슈 번호를 물어봅니다
